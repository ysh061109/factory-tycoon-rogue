# 기획서 (가제: 이름 미정)

> 상태: 초안 2. 사용자가 말한 내용은 **[확정]**, Claude가 정리하면서 덧붙인 내용은 **[제안]**, 아직 정해야 할 것은 **[미정]**으로 표시합니다.

## 1. 한 줄 콘셉트

Create로 만든 공장 생산품을 주민에게 납품하고, 공장을 구경하러 온 주민에게 평가받아 돈을 버는 **로그라이크 + 타이쿤 + 시뮬레이션** 애드온. 라운드가 끝날 때마다 카드를 골라 공장과 가게를 성장시킵니다. 주민은 저마다 성향과 취향이 다르고, 평점과 소문, SNS, 뉴스로 이어지는 살아 있는 마을 시스템이 핵심입니다. **[확정]**

## 2. 기술 전제

- Minecraft 1.21.1, NeoForge **[확정]**
- Create 6.0.x 애드온 **[확정]** (1단계는 Create 없이도 동작하게 만들고, 이후 연동 **[제안]**)
- 개발과 빌드는 Claude가 담당하고, 빌드는 GitHub Actions로 jar를 생성 **[확정]**
- 외부 모드 연동은 모두 **선택 의존성**: 해당 모드가 없어도 우리 모드는 정상 동작 **[제안]**
  - Create: Numismatics (화폐) **[확정]**
  - TACZ, Superb Warfare (총기 반응) **[확정]**
    - 확인 결과: TACZ는 비공식 NeoForge 1.21.1 포트가 있고, Superb Warfare 0.8.5는 1.21.1 NeoForge를 지원합니다.
- 상세 아이디어는 사용자가 계속 추가 **[확정]**

## 3. 핵심 게임 루프

1. 주민이 공장 생산품을 **대량으로 주문**합니다. 예: 철 도구 200개 납품 **[확정]**
2. 플레이어는 Create 공장을 만들고 확장해서 주문을 처리합니다.
3. 주민이 **공장을 직접 보러 와서 평가**하고 돈을 줍니다. **[확정]**
4. 라운드가 끝나면 **카드 3장 중 1장을 선택**해 업그레이드합니다. **[확정]**
5. 평판이 오르면 더 많고 더 부유한 방문객이 찾아옵니다. **[확정: 방문객 증가]**
6. 다음 라운드는 더 큰 주문과 새로운 조건으로 시작합니다. (로그라이크 요소) **[제안]**

## 4. 재화

- 기본 재화는 **에메랄드** **[확정]**
- Create: Numismatics가 설치되어 있으면 그 화폐로 거래 **[확정]**
- 구현: 지불 방식을 추상화해서, 에메랄드와 Numismatics를 같은 인터페이스로 처리 **[제안]**

## 5. 카드 시스템

사용자가 준 예시:
- 공장 인기 증가로 **방문객 증가** **[확정]**
- **도구 수요 증가** **[확정]**

Claude가 정리한 카드 분류 **[제안]**:

| 분류 | 효과 예시 |
|---|---|
| 방문객 | 방문객 수 증가, 부유한 방문객 출현 확률 증가 |
| 수요 | 특정 품목(도구, 음식 등) 주문량과 단가 증가 |
| 평가 | 평가 점수 보너스, 평판 획득량 증가 |
| 취향 | 특정 취향(커피, 자동차 등) 손님 출현 증가 |
| 리스크 | 주문량 2배, 보상도 2배 / 제한시간 단축, 보상 증가 |
| 자동화 | 공장 속도 증가, 납품 자동화 보조 |
| 특수 | 특별 손님(유튜버 등) 방문, 일회성 대박 주문 |

- 카드는 데이터 파일(JSON)로 정의해서, 코드를 건드리지 않고 카드를 추가하고 수정할 수 있게 합니다. **[제안]**
- 희귀도(일반, 희귀, 전설)를 두고 라운드가 진행될수록 좋은 카드가 나오게 합니다. **[제안]**

## 6. 주민(손님) 시스템

### 6-1. 성향 **[확정: 주민마다 성향이 다름]**

- 주민마다 성격 수치(예: 까다로움, 너그러움, 겁 많음, 수다스러움, 소문 좋아함)를 무작위로 가집니다. **[제안]**
- 성향이 구매 행동, 평가 점수, 대화 내용, 위협을 받았을 때의 반응을 모두 결정합니다. **[제안]**
- "AI"는 규칙과 점수 기반 의사결정(유틸리티 AI)으로 구현합니다. 외부 AI 서버를 쓰는 대화 생성은 게임 안에서 안정적으로 쓰기 어려워서 권장하지 않습니다. **[제안]**

### 6-2. 취향 **[확정]**

사용자가 준 취향 예시: 역사, 자동차, 비행기, 커피, 콜라 등

- 주민마다 좋아하는 취향 1~3개를 가집니다.
- 그 취향에 맞는 물건을 생산하는 공장을 만들면 만족도와 평가가 올라갑니다. **[확정]**
- 구현: 취향 카테고리와 아이템 목록을 데이터 파일로 연결하고, 다른 모드 아이템도 데이터팩으로 추가할 수 있게 합니다. **[제안]**

## 7. 공장 평가

주민이 공장을 보고 평가한다는 아이디어는 구현 난이도가 가장 높습니다. 현실적인 평가 방식 **[제안]**:

- 생산량과 가동률
- 생산 품목의 다양성
- 주민 취향과의 일치도 (6-2)
- 공장 규모(범위 안의 Create 부품 수)
- 평가 구역을 만들어 주면, 방문객이 그 안을 돌아다니며 구경

공장의 "외관 점수"는 처음에는 넣지 않고, 위의 수치 기반 평가로 시작합니다.

## 8. 총기 위협과 평판

### 8-1. 총기 반응 **[확정]**

- 플레이어가 주민에게 총을 겨누면 주민이 **겁먹고 도망**갑니다.
- 연동 대상: TACZ, Superb Warfare 등 총기 모드

구현 방식 **[제안]**:
1. 기본 감지: 총기 태그가 붙은 아이템을 든 채 주민을 일정 시간 바라보면 위협으로 판정. 어떤 총기 모드에도 적용 가능
2. 정밀 감지: TACZ, Superb Warfare의 조준 상태를 직접 읽어서 정확히 판정 (모드별로 따로 작업)
3. 겁먹은 연출은 1차로 도망 AI, 파티클, 효과음, 말풍선 대사로 구현. 손을 드는 등 전용 애니메이션은 난이도가 높아서 이후 단계로 미룸

### 8-2. 평점과 소문 **[확정]**

- 위협을 받으면 해당 주민의 평점이 깎입니다.
- 목격한 주민이 소문을 퍼뜨리고, 소문은 다른 주민의 호감도와 방문객 수에 영향을 줍니다. 성향이 "소문 좋아함"인 주민은 더 많이 퍼뜨립니다. **[제안]**
- 평판 회복 이벤트(사과 보상, 기부 등)를 둡니다. **[제안]**

## 9. SNS와 뉴스 **[확정]**

구현 방식 **[제안]**:
- 게임 안에서 휴대폰 아이템이나 게시판 블록으로 열어보는 전용 화면
- **SNS**: 주민들이 올리는 리뷰와 후기, 소문 글. 성향과 평점에 따라 내용이 달라집니다.
- **뉴스**: 오늘의 헤드라인. 예) "철 도구 품귀", "커피 열풍", "한 공장에서 총기 소동"
- 뉴스가 게임에 영향을 줍니다. 유행 품목이 생겨 수요가 오르고, 사건 기사는 평판에 반영됩니다.

## 10. 대화 시스템 **[확정]**

- 주민 대화는 채팅창이 아니라 **주민 머리 위에 뜨는 전용 말풍선 창**으로 표시
- **한국어와 영어** 지원 (번역 파일로 구현해서, 이후 다른 언어도 추가 가능) **[제안]**
- 대사는 성향, 취향, 상황(주문, 칭찬, 불만, 총을 겨눔 등)에 따라 골라서 출력 **[제안]**

## 11. 개발 단계 **[제안]**

| 단계 | 내용 | 난이도 |
|---|---|---|
| 1단계 | 주문 생성, 아이템 납품, 에메랄드 보상, 카드 선택 UI | 보통 |
| 2단계 | 주민 성향과 취향, 머리 위 말풍선 대화(한/영) | 보통 |
| 3단계 | 평점, 소문, 총기 위협 반응(기본 감지) | 보통~어려움 |
| 4단계 | SNS, 뉴스 화면 | 보통~어려움 |
| 5단계 | 공장 평가와 방문객 시스템 | 어려움 |
| 6단계 | Numismatics, TACZ, Superb Warfare 정밀 연동, 전용 애니메이션 | 어려움 |

현재 진행 상황: 빈 모드 뼈대와 자동 빌드 설정까지 완료.

## 12. 아직 정해야 할 것 **[미정]**

- 모드 이름
- 라운드 길이: 마인크래프트 며칠 단위인지, 실시간 몇 분인지
- 실패 조건: 라운드 목표 미달 시 어떤 불이익이 있는지(게임 오버가 있는지)
- 멀티플레이 지원 여부
- 주문과 납품 방식: 전용 블록에 넣는지, Create 컨베이어로 자동 납품하는지
- 주민은 기존 바닐라 주민을 쓸지, 이 모드 전용 손님 엔티티를 새로 만들지 (전용 엔티티가 말풍선과 애니메이션을 다루기 쉽습니다)
